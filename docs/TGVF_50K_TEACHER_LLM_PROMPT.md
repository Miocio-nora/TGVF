# TGVF 50K Teacher LLM Prompt

This document records the LLM prompt used to generate the V4 50K teacher data
family that later became the clean Stage1/Stage2 splits.

## Run Identity

Generation launcher:

```text
scripts/run_tgvf_v4_teacher_50k.py
```

The launcher calls `resume_sync(...)` with:

```text
selection: data/tgvf_teacher/preparation/selections/selected_images_v3_50k_v0.jsonl
run_id default: tgvf_v4_teacher_50k
model default: gpt-5.4
image_detail default: original
target_accepted_samples: 50000
temperature default: 0.2
max_output_tokens default from launcher: 5000
timeout_seconds default from launcher: 180
prompt_version: tgvf_v4_teacher
schema_version: tgvf_teacher_schema_v4
confidence_threshold: 0.75
```

Current clean train/test splits derived from this family:

```text
data/tgvf_teacher/generated/runs/tgvf_v4_teacher_50k_clean_imend_open_answer/splits/tgvf_v4_teacher_stage2_protocol_c.train.jsonl
data/tgvf_teacher/generated/runs/tgvf_v4_teacher_50k_clean_imend_open_answer/splits/tgvf_v4_teacher_stage2_protocol_c.test.jsonl
```

The split rows retain:

```text
teacher_prompt_version: tgvf_v4_teacher
```

## Request Shape

The OpenAI Responses payload is assembled by
`src/tgvf_data/generate_teacher.py::build_responses_payload`.

For V4, the request has this logical structure:

```text
input:
  - role: developer
    content:
      - type: input_text
        text: TEACHER_PROMPT_V4
  - role: user
    content:
      - type: input_text
        text: build_v4_user_message(image_record, source_context)
      - type: input_image
        image_url: image_reference
        detail: original

text.format:
  type: json_schema
  name: tgvf_teacher_schema_v4
  strict: true
  schema: teacher_output_schema_v4()

temperature: 0.2
max_output_tokens: 5000
```

The JSON schema is generated by
`src/tgvf_data/tgvf_teacher_schema_v4.py::teacher_output_schema_v4`.

## Developer Prompt

Exact `TEACHER_PROMPT_V4`:

```text
You are a meticulous visual re-focus trace annotator for training a multimodal model.

We are building a static-image Target-Guided Visual Foveation system, abbreviated TGVF.

Your job is to inspect the provided image and generate teacher-data items in schema_version "tgvf_teacher_schema_v4" and teacher_version "tgvf_v4_teacher".

The generated data should teach a model this behavior:

1. It sees an image and a question, optionally with choices.
2. It reasons naturally inside <think>...</think>.
3. It decides whether current visual evidence is sufficient.
4. If visual evidence is insufficient, it emits exactly one encoder-facing visual focus descriptor inside <|focus_start|>...<|focus_end|>.
5. A visual module returns TGVF visual embeddings.
6. The model reads out focused visual evidence in a later <think>...</think> span.
7. It continues reasoning and answers.

Important conceptual rule:

The focus text is NOT a structured tool-call object.
The focus text is NOT a task instruction to the assistant.
The focus text is NOT just a region name.

The focus text is an encoder-facing visual descriptor. It describes the visual evidence that should be re-encoded: the local region or anchors, the visual aspect that matters, and the surrounding context that should be preserved.

Reasoning intent stays in the think text.
Visually grounded re-encoding description stays in the focus text.

Return strict JSON only.
Do not include markdown.
Do not include explanations outside JSON.
Do not hallucinate.
If reliable visual evidence is not present, skip the item.
Only include items with confidence >= 0.75.
```

## User Prompt Template

`build_v4_user_message(image_record, source_context)` prepends image metadata
and a source-profile hint before the static V4 user instruction block.

The complete text template is:

```text
Image metadata:
- stable_image_uid: {stable_image_uid}
- source_dataset: {source_dataset}
- source_profile: {source_profile}

{source_profile_hint_v4(source_profile)}

You are given one image.
Generate TGVF V4 teacher annotations from this image.

Return a strict JSON object with this top-level schema:

{
  "schema_version": "tgvf_teacher_schema_v4",
  "teacher_version": "tgvf_v4_teacher",
  "image_id": "optional string if available, otherwise null",
  "image_summary": "one concise whole-image description",
  "items": [ ... ]
}

Each item must follow this schema:

{
  "item_id": "optional stable id, otherwise null",
  "item_type": "single_refocus | multi_refocus | no_refocus_continue | no_refocus_answer",
  "answer_format": "open | multiple_choice",
  "question_type": "color_attribute | texture_material | pattern | shape_boundary | object_part | spatial_relation | counting | state_action | ocr_text | number_reading | chart_table | diagram_visual_fact | math_reasoning | whole_image_obvious | other",
  "focus_category": "color_surface | surface_detail | material_cue | pattern_detail | shape_boundary | object_part_detail | relation_layout | group_counting | contact_state | text_region | number_region | chart_table_region | diagram_region | none",
  "question": "natural question about the image",
  "choices": [
    {"label": "A", "text": "..."},
    {"label": "B", "text": "..."},
    {"label": "C", "text": "..."},
    {"label": "D", "text": "..."}
  ],
  "correct_choice": "A | B | C | D | null",
  "answer_text": "plain answer text without option label when possible",
  "trace": [ ... ],
  "quality": {
    "confidence": 0.0,
    "num_focus_steps": 0,
    "notes": "optional short note, otherwise null"
  }
}

Trace step schemas:

Think step:
{"type": "think", "text": "natural reasoning text"}

Focus step:
{
  "type": "focus",
  "focus_text": "encoder-facing visual descriptor",
  "focused_evidence": "one concise grounded description of what the focused visual evidence shows",
  "metadata": {
    "evidence_type": "ocr_text | number | document_field | chart_value | table_cell | logo_symbol | object_part | color_attribute | texture_material | pattern | shape_boundary | spatial_relation | counting | state_action | diagram_detail | math_visual_fact | other",
    "focus_descriptor_cues": ["location", "nearby_anchor", "surface", "texture", "pattern", "color", "shape", "size", "text_like", "number_like", "chart_anchor", "table_anchor", "object_part", "material_cue", "relation", "contact_area"],
    "target_leakage_risk": "none | low | medium | high",
    "confidence": 0.0
  }
}

Answer step:
{"type": "answer", "text": "final answer; for multiple choice, include option label and answer text, for example 'B. rubber'"}

Trace shape rules:

single_refocus:
- Must contain exactly one focus step.
- Must contain at least: think, focus, think, answer.
- quality.num_focus_steps must be 1.

multi_refocus:
- Must contain exactly two focus steps.
- Must follow this pattern: think, focus, think, focus, think, answer.
- quality.num_focus_steps must be 2.
- The second focus must depend on evidence learned from the first focus.
- Do not create 3-focus examples.

no_refocus_continue:
- Must contain no focus steps.
- Must contain think + answer.
- Use when visual evidence is already sufficient, but reasoning, calculation, comparison, or symbolic manipulation is still needed.
- Do not request focus merely because reasoning is not finished.

no_refocus_answer:
- Must contain no focus steps.
- Must contain think + answer.
- Use when the answer is obvious from the full image and no local re-perception is useful.

Focus text rules:

The focus_text must be a visually grounded descriptor of visual evidence for re-encoding.
It should usually be 6 to 24 words.
It should describe:
- visual region or visual anchors;
- visual aspect that matters;
- surrounding context to preserve, if needed.

Good focus_text examples:
- close-up surface texture, folds, and sheen of the glove
- visible color region across the lock surface
- fine woven pattern across the scarf fabric
- rough grain pattern on the wooden tabletop
- glossy highlights and smooth surface of the bottle
- outer contour and full boundary of the wall sign
- small hinge and clasp area on the bag strap
- the person's fingers, phone edge, and contact area
- entire cluster of small visible objects on the shelf
- wide shared view containing the dog, the river, and the space between them
- the tallest bar together with nearby y-axis tick labels
- the second-row third-column cell with its row and column headers
- legend entries and color swatches beside the chart
- the matching chart bar and nearby y-axis tick labels

Bad focus_text examples:
- the glove
- the object
- the upper-left area
- something
- texture_material
- tight_crop
- determine the material of the glove
- inspect the lock to answer the question
- compare the dog and river to judge left or right
- count the objects on the shelf
- read the value of the tallest bar
- verify whether the person is holding the object
- the answer
- the red logo, if the question asks what color the logo is
- the rubber glove, if the question asks what material the glove is
- the number 42, if the question asks what number is shown
- the word STOP, if the question asks what word is printed

Operational focus_text constraints:
- Prefer visually grounded noun phrases or short visual descriptions.
- Avoid bare object names.
- Avoid abstract reasoning verbs and answer-oriented verbs, especially: determine, judge, answer, verify, decide, infer, whether.
- Avoid putting choices or answer values in focus_text.
- For OCR, prefer "high-resolution small printed text line below the barcode" over "read the text below the barcode".
- For relation, prefer "wide shared view containing the dog, the river, and the space between them" over "compare the dog and river".
- For counting, prefer "entire cluster of small visible objects on the shelf" over "count the objects on the shelf".
- For material, prefer "close-up surface texture and sheen of the glove" over "determine the glove material".

Think text rules:

Pre-focus think:
- Natural and concise.
- Connect the question to what is visible in the full image.
- For refocus items, explain why focused visual evidence is useful.
- Must not reveal the answer value before the focus step.
- Do not use field-like phrasing such as "known_visual_evidence" or "missing_or_uncertain_info".
- Avoid repetitive template wording.

Post-focus think:
- Read out the focused evidence naturally.
- May mention the answer value because it occurs after focused visual input.
- May continue reasoning if needed.
- For multi_refocus, the think after the first focus should explain what was learned and what visual detail is still missing.

No-refocus think:
- Clearly distinguish visual sufficiency from reasoning incompleteness.
- For no_refocus_continue, say that no additional visual evidence is needed, then continue the reasoning.
- For no_refocus_answer, keep it short and answer.

Distribution goals:

V4 is focus-heavy. Do not make no-refocus half the data.

For this image, generate:
- 3 to 6 refocus-capable items if reliable visual details exist.
- At most 1 multi_refocus item.
- 0 to 1 no_refocus_continue item if supported.
- 0 to 1 no_refocus_answer item if supported.
- Fewer items if the image does not support reliable details.

Dataset-level targets, for reference:
- single_refocus: about 70% to 75%
- multi_refocus: about 5% to 10%
- no_refocus_continue: about 5% to 10%
- no_refocus_answer: about 5% to 10%

Question and focus category balance:

Do not let location, nearby_anchor, region_type, text_like, OCR, number reading, document fields, chart values, or table cells dominate.

Important distinction:
- question_type is the main balancing category.
- focus_category is the second main balancing category.
- focus_descriptor_cues are auxiliary locatability or descriptor cues, not the main target type.

Prioritize underrepresented visual-detail categories when the image supports them:
1. color_attribute
2. texture_material
3. pattern
4. shape_boundary
5. object_part
6. spatial_relation
7. counting
8. state_action/contact

Approximate refocus question_type targets across the full dataset:
- color_attribute: 14% to 18%
- texture_material: 14% to 18%
- pattern: 5% to 8%
- shape_boundary: 8% to 12%
- object_part: 8% to 12%
- spatial_relation: 10% to 14%
- counting: 8% to 12%
- state_action: 6% to 10%
- ocr_text + number_reading: cap around 12% to 15%
- chart_table: cap around 6% to 10%
- diagram_visual_fact: 3% to 6%

Anti-OCR dominance:
- Do not overproduce OCR, text_like, number_like, document_field, chart_value, or table_cell items.
- For ordinary natural images, generate at most 1 OCR/text/number item.
- For document/chart/table/receipt/sign/package-heavy images, generate at most 2 OCR/text/number items.
- If the image supports color, texture, material, pattern, shape, object-part, state/action, relation, or counting questions, prioritize those before OCR-like questions.
- If the image only supports text-like evidence, generate fewer items rather than filling the quota with OCR.

Visual-detail priority:
- Actively create questions about local color, surface texture, material cues, repeated patterns, shape boundaries, object parts, contact states, and small physical details.
- These examples are important because V4 should teach focus_text to control how the visual encoder reprocesses the image, not only where it looks.

Multiple-choice requirements:

Increase multiple-choice coverage.
Aim for about 40% to 60% multiple-choice items across the dataset.
Use multiple-choice when natural, especially for:
- color_attribute
- texture_material
- pattern
- shape_boundary
- object_part
- spatial_relation
- counting
- state_action
- chart_table
- diagram_visual_fact

Choice rules:
- Use 2 to 4 choices; prefer 4 choices when natural.
- Distractors must be plausible and same-type.
- Avoid absurd distractors that can be eliminated by language alone.
- Choices must not leak into focus_text.
- For multiple-choice answer, final answer should include both label and text, for example "B. rubber".

Leakage rules:

focus_text must not:
- include answer_text or the correct choice text;
- include exact text, number, date, code, label, or word that the question asks the model to read;
- include final color, material, texture, count, direction, or attribute value if that value is the answer;
- include option labels as part of the visual descriptor;
- include special tokens such as <|endoftext|>, <|im_end|>, <think>, <|focus_start|>, or <|focus_end|>;
- contain pipes or malformed delimiter-like fragments.

For refocus items, pre-focus think must not reveal the answer before focus.
Focused_evidence may contain the answer value because it represents evidence available after re-focus.

Privacy and safety:
- Do not create items revealing personal addresses, phone numbers, email addresses, government IDs, financial account numbers, or other sensitive personal identifiers.
- Skip such details even if visible.
- Generic product labels, public signs, chart labels, package text, non-sensitive dates, and non-personal document fields are allowed.

Multi-focus rules:

Use multi_refocus sparingly.
Create at most one multi_refocus item for this image.
Create multi_refocus only when a genuine two-step visual evidence chain is needed.

Quality rules:
- Skip blurry, ambiguous, or hallucinated evidence.
- Prefer fewer reliable items over many weak ones.
- Avoid duplicate questions from the same image.
- Avoid global scene captions in refocus items.
- Accepted confidence must be >= 0.75.
- Set target_leakage_risk to none, low, medium, or high.
- Prefer none or low leakage risk. Skip medium/high risk items unless truly unavoidable.

Output now: strict JSON only.

{optional source context block, if provided}
```

The optional source context block is appended only when `source_context` is
non-empty:

```text

Optional source context is provided below. Use it only as a hint and verify it from the image.
{source_context}
```

## Source-Profile Hints

The `{source_profile_hint_v4(source_profile)}` placeholder expands to one of:

```text
natural_image:
Prefer visual-detail traces: color, texture/material, pattern, shape, object parts, contact states, relations, and counting. Avoid OCR dominance.

scene_text:
Generate at most two OCR/number traces; also look for color, surface, logo/symbol, relation, and object-part details.

document:
Prefer fields/tables only when reliable; include no_refocus_continue for clearly readable reasoning/calculation when appropriate.

chart:
Prefer chart/table reasoning with MC choices; use multi_refocus only for genuine legend/header then value chains.

table:
Prefer row/column/header focused traces and no_refocus_continue when the table is globally readable.

fallback:
Prefer reliable V4 traces; do not force unavailable categories.
```
